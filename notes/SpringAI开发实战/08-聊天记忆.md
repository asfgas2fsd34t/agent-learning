# 08 聊天记忆

> 来源：Spring AI 官方文档 `api/chat-memory.html`（1.1.x）。

## 学习目标

- 分清 Chat Memory 与 Chat History
- 理解 ChatMemory（策略）+ ChatMemoryRepository（存储）两层
- 掌握 MessageWindowChatMemory 窗口语义
- 会用记忆 Advisor 三件套
- 能自定义压缩记忆、用 PG 存储、处理多数据源

## 1. 核心心智模型

```text
ChatMemory  = 窗口化的"模型上下文"（下一次调用要带哪些消息）
ChatHistory = 全量"账本"（完整对话记录，审计/回放用）
两者不同！记忆超窗会被丢弃/替换；历史要用 Spring Data 另存。

ChatMemory（策略层）：加消息、取消息、裁剪
ChatMemoryRepository（存储层）：saveAll 全量替换、findByConversationId
```

用户问"就是模型上下文呗类似"——对，memory ≈ 下次请求送给模型的上下文窗口内容；history 是数据库里的完整记录。

## 2. 两层接口

```java
public interface ChatMemory {
    void add(String conversationId, List<Message> messages);
    List<Message> get(String conversationId);       // 按策略取（窗口裁剪后）
    void clear(String conversationId);
}

public interface ChatMemoryRepository {
    void saveAll(String conversationId, List<Message> messages);  // 全量替换
    List<Message> findByConversationId(String conversationId);
    void deleteByConversationId(String conversationId);
}
```

要点：`saveAll` 是**全量替换**语义——策略层每次把裁剪后的完整列表存回去。

## 3. MessageWindowChatMemory 窗口语义

```java
ChatMemory memory = MessageWindowChatMemory.builder()
    .maxMessages(20)      // 默认 20
    .build();
```

- 默认保留最近 **20 条**消息；system 消息始终保留
- 超窗时**丢弃最旧的**（不是压缩！）

### LLM 会自动压缩吗？——不会

常见误解："上下文窗口满了 LLM 会自动压缩"。事实：

- 模型**不会**自动压缩历史；超窗会**报错**（超过 max context length）或被静默截断
- 窗口裁剪是**应用层**（ChatMemory 策略）的事
- 想要"压缩"效果必须自己实现（见 6）

不设窗口大小行不行？不行——`maxMessages` 就是防止无限增长把模型窗口撑爆的闸门。模型有上下文上限（如 128K token），应用不裁剪，最终要么报错要么成本失控。

## 4. 记忆 Advisor 三件套

| Advisor | 状态 | 说明 |
|---------|------|------|
| MessageChatMemoryAdvisor | ✅ 推荐 | 历史作为 Message 列表注入 |
| PromptChatMemoryAdvisor | ⚠️ 1.1.3 起废弃 | 历史渲染进 prompt 文本 |
| VectorStoreChatMemoryAdvisor | ✅ 长记忆 | 向量检索式记忆，memory-entry XML 转义防注入 |

装配：

```java
ChatClient chatClient = ChatClient.builder(chatModel)
    .defaultAdvisors(MessageChatMemoryAdvisor.builder(memory).build())
    .build();

// 每次调用必须传 conversationId！
chatClient.prompt()
    .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, "user-42-session-1"))
    .user("我叫小曾")
    .call().content();
```

`ChatMemory.CONVERSATION_ID` 是约定的运行时参数 key（详见 02 第 5 节）：不传或忘传，会话就串了。

## 5. PG 做 Repository

用官方 `JdbcChatMemoryRepository` + `PostgresChatMemoryRepositoryDialect`，表结构官方直接给：

```sql
CREATE TABLE IF NOT EXISTS SPRING_AI_CHAT_MEMORY (
    conversation_id VARCHAR(36) NOT NULL,
    content TEXT NOT NULL,
    type VARCHAR(10) NOT NULL CHECK (type IN ('USER', 'ASSISTANT', 'SYSTEM', 'TOOL')),
    "timestamp" TIMESTAMP NOT NULL
);
CREATE INDEX IF NOT EXISTS SPRING_AI_CHAT_MEMORY_CONVERSATION_ID_TIMESTAMP_IDX
ON SPRING_AI_CHAT_MEMORY(conversation_id, "timestamp");
```

```java
ChatMemoryRepository repository = JdbcChatMemoryRepository.builder()
    .jdbcTemplate(jdbcTemplate)
    .dialect(new PostgresChatMemoryRepositoryDialect())
    .build();

ChatMemory memory = MessageWindowChatMemory.builder().build(); // 默认拿 repository 自动装配
```

## 6. 自定义压缩记忆：SummarizingChatMemory

思路（三段式组装）：

```text
get(conversationId) 返回：
  1. SystemMessage（原样保留）
  2. [历史摘要] SystemMessage（旧消息压缩成的摘要）
  3. 最近 retainRecent 条消息（原文保留）

add() 时：若总条数 > maxMessages，把最旧的滚进摘要
```

```java
public class SummarizingChatMemory implements ChatMemory {

    private final ChatMemoryRepository repository;
    private final ChatModel summarizer;      // 必须是裸 ChatModel，别再挂记忆 Advisor，否则递归！
    private final int maxMessages;
    private final int retainRecent;

    public SummarizingChatMemory(ChatMemoryRepository repository,
                                 ChatModel summarizer,
                                 int maxMessages, int retainRecent) {
        this.repository = repository;
        this.summarizer = summarizer;
        this.maxMessages = maxMessages;
        this.retainRecent = retainRecent;
    }

    @Override
    public synchronized void add(String conversationId, List<Message> messages) {
        List<Message> all = new ArrayList<>(repository.findByConversationId(conversationId));
        all.addAll(messages);
        if (all.size() > maxMessages) {
            List<Message> toSummarize = all.subList(0, all.size() - retainRecent);
            String summary = summarize(toSummarize, findExistingSummary(all));
            List<Message> kept = new ArrayList<>();
            kept.add(new SystemMessage("[历史摘要] " + summary));
            kept.addAll(all.subList(all.size() - retainRecent, all.size()));
            all = kept;
        }
        repository.saveAll(conversationId, all);   // 全量替换
    }

    @Override
    public synchronized List<Message> get(String conversationId) {
        return repository.findByConversationId(conversationId);
    }

    @Override
    public synchronized void clear(String conversationId) {
        repository.deleteByConversationId(conversationId);
    }

    private String summarize(List<Message> old, String existingSummary) {
        StringBuilder sb = new StringBuilder();
        if (existingSummary != null) sb.append("已有摘要：").append(existingSummary).append("\n");
        sb.append("请把以下对话压缩成简洁摘要（保留事实、决定、待办）：\n");
        for (Message m : old) {
            sb.append(m.getMessageType()).append(": ").append(m.getText()).append("\n");
        }
        return summarizer.call(new Prompt(sb.toString()))
                .getResult().getOutput().getText();
    }

    private String findExistingSummary(List<Message> all) {
        return all.stream()
                .filter(m -> m.getMessageType() == MessageType.SYSTEM
                        && m.getText() != null && m.getText().startsWith("[历史摘要]"))
                .map(m -> m.getText().substring(5))
                .findFirst().orElse(null);
    }
}
```

装配（与 JdbcChatMemoryRepository、MessageChatMemoryAdvisor 组合）：

```java
ChatMemory memory = new SummarizingChatMemory(repository, summarizerModel, 20, 6);
ChatClient chatClient = ChatClient.builder(chatModel)
    .defaultAdvisors(MessageChatMemoryAdvisor.builder(memory).build())
    .build();
```

## 7. 多数据源怎么办

自动配置 `JdbcChatMemoryRepositoryAutoConfiguration` 注入的是**主 JdbcTemplate/DataSource**（@Primary 那个）——业务库和记忆库分开时会拿错库。根治：手动定义 Bean，`@ConditionalOnMissingBean` 让自动配置让位：

```java
@Configuration
public class DataSourceConfig {

    @Bean @Primary
    public DataSource businessDataSource(...) { ... }   // 业务库

    @Bean
    public DataSource memoryDataSource(...) { ... }     // 记忆库

    @Bean @Primary
    public JdbcTemplate businessJdbcTemplate(...) { ... }

    @Bean
    public JdbcTemplate memoryJdbcTemplate(...) { ... }

    // 手动钉死用记忆库的 JdbcTemplate
    @Bean
    public ChatMemoryRepository chatMemoryRepository(JdbcTemplate memoryJdbcTemplate) {
        return JdbcChatMemoryRepository.builder()
                .jdbcTemplate(memoryJdbcTemplate)
                .dialect(new PostgresChatMemoryRepositoryDialect())
                .build();
    }
}
```

注意：**只有 1 个记忆 repository**。业务数据走你自己的 DAO/JPA，不要幻想"businessMemoryRepository"这种东西——业务库的读写和记忆是两码事。

## 8. ChatMemoryRepository 要不要自定义

多数情况**不需要**：Jdbc/Memory/Neo4j 等官方实现够用，摘要只是存成 SystemMessage（见 6），存储层无感知。只有存储介质官方没有（比如自研缓存、加密存储）才自己实现接口。

## 9. 生产边界

- conversationId 要全局唯一且稳定（用户 id + 会话 id）
- 记忆表内容含用户隐私，注意脱敏与保留策略
- 摘要用的 summarizer 模型可以选便宜小模型
- add/clear 加 synchronized（或靠单线程调度），Repository 的 saveAll 是全量替换有竞态风险
