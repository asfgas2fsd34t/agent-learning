# 05 结构化输出

> 来源：Spring AI 官方文档 `api/structured-output-converter.html`（1.1.x）。

## 学习目标

- 理解 StructuredOutputConverter = 格式说明 + 解析器
- 掌握 `entity()` 一行拿强类型结果
- 理解泛型擦除与 `ParameterizedTypeReference` 对策
- 了解 Native Structured Output

## 1. 核心心智模型

```text
LLM 输出的是文本字符串 → 想要 Java 对象需要"格式约定 + 解析"
StructuredOutputConverter<T> = Converter<String, T>（解析） + FormatProvider（把格式要求注入 prompt）
ChatClient.entity() 封装了这两步
```

工作流：getFormat() 生成"请按此 JSON Schema 输出"的说明 → 追加进 prompt → 模型输出 JSON → convert() 反序列化 → 校验失败可走递归重试（03 的 StructuredOutputValidationAdvisor）。

## 2. 快速上手

```java
record ActorFilms(String actor, List<String> movies) {}

ActorFilms films = chatClient.prompt()
    .user("生成汤姆·汉克斯的电影作品")
    .call()
    .entity(ActorFilms.class);
```

## 3. 泛型集合：ParameterizedTypeReference 骗过泛型擦除

```java
List<ActorFilms> list = chatClient.prompt()
    .user("生成两位演员的电影作品")
    .call()
    .entity(new ParameterizedTypeReference<List<ActorFilms>>() {});
```

### 什么是 Java 泛型擦除

Java 泛型只在**编译期**检查，编译后类型参数被擦掉——`List<ActorFilms>` 和 `List<String>` 在运行时都只是 `List`。所以 `entity(List<ActorFilms>.class)` 这种写法不存在。

`ParameterizedTypeReference<T>` 的对策：匿名子类 `new ParameterizedTypeReference<List<ActorFilms>>() {}` 在**编译时把泛型签名保留在字节码里**（匿名类携带泛型信息），运行时通过反射读取——这叫"骗过"擦除。

## 4. 三种内置 Converter

| Converter | 目标类型 | 说明 |
|-----------|---------|------|
| BeanOutputConverter | POJO/record | 最常用，基于 Jackson，支持 JSR-303 校验 |
| MapOutputConverter | Map<String, Object> | 字段不定时 |
| ListOutputConverter | List\<T\> | 返回逗号分隔文本并解析成列表 |

底层使用（不走 ChatClient 时）：

```java
BeanOutputConverter<ActorFilms> converter = new BeanOutputConverter<>(ActorFilms.class);
String format = converter.getFormat();           // 注入 prompt 的格式说明
// ... 拿到模型输出 text ...
ActorFilms films = converter.convert(text);
```

## 5. Native Structured Output

把 JSON Schema 直接交给模型 API（各家 JSON mode / response_format），由模型保证输出合法 JSON，而不是靠 prompt 约定：

```java
chatClient.prompt()
    .advisors(a -> a.param(AdvisorParams.ENABLE_NATIVE_STRUCTURED_OUTPUT, true))
    .user("...")
    .call().entity(ActorFilms.class);
```

各家 JSON mode 配置不同（OpenAI `response_format=json_schema`、Ollama `format`、Anthropic 工具模拟等），以实际服务文档为准。适合对 JSON 合法性要求高的生产场景；降级策略：模型不支持时自动回退 prompt 方式。

## 6. 选择建议

| 场景 | 方案 |
|------|------|
| 单个对象 | `entity(Xxx.class)` |
| 泛型集合 | `entity(new ParameterizedTypeReference<...>(){})` |
| 合规要求高 / 生产 | Native Structured Output + 校验 |
| 字段不确定 | MapOutputConverter |

## 7. 生产边界

- record/POJO 字段名要和 Schema 一致，加 Jackson 注解处理命名差异
- 模型可能输出带解释文字的 JSON——BeanOutputConverter 会提取 ```json 代码块，但建议提示词明确"只输出 JSON"
- 复杂嵌套结构配合递归校验 Advisor（03）做失败重试
