# 16 可观测性（监控）

> 来源：Spring AI 官方文档 `observability/index.html`（1.1.x）。

## 学习目标

- 理解 Spring AI 监控 = Micrometer 指标 + 分布式追踪（Spring 生态原生）
- 掌握各组件的观测点与关键标签（prompt/工具/向量库）
- 会开敏感数据记录开关并知道风险
- 看懂 Prometheus 指标命名与 Active/Completed 区别

## 1. 核心心智模型

```text
Spring AI 监控 = 复用 Spring 生态的 Micrometer（metrics + tracing）
前置：spring-boot-starter-actuator（唯一要加的依赖）
覆盖：ChatClient（含 Advisor）、ChatModel、EmbeddingModel、ImageModel、VectorStore、Tool Calling
遵循 OpenTelemetry 的 Generative AI 语义约定（gen_ai.* 命名）

两条铁律：
① 低基数 key（模型名、是否流式）→ 进 metrics + traces；高基数 key（prompt、conversation id）→ 只进 traces
② prompt/completion/工具入参出参等敏感大数据 → 默认不导出，开关手动开
```

```xml
<dependency>
 <groupId>org.springframework.boot</groupId>
 <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

（对接 Prometheus/Grafana/Zipkin 是标准 Spring Boot Actuator/Micrometer 配置，Spring AI 侧零代码。）

## 2. ChatClient 观测（spring.ai.chat.client）

`call()`/`stream()` 触发，度量耗时并传播 trace。

低基数：`gen_ai.operation.name=framework`、`gen_ai.system=spring_ai`、`spring.ai.chat.client.stream`（true/false）、`spring.ai.kind=chat_client`。

高基数（只进 trace）：`gen_ai.prompt`（prompt 内容，可选）、`spring.ai.chat.client.advisors`（挂了哪些 Advisor）、`spring.ai.chat.client.conversation.id`（记忆会话 id）、`spring.ai.chat.client.tool.names`（工具名列表）。

**Prompt/Completion 记录开关**（默认全关，开了注意敏感信息风险）：

```yaml
spring:
  ai:
    chat:
      client:
        observations:
          log-prompt: false      # 记录 prompt 内容
          log-completion: false  # 记录回答内容
```

## 3. Advisor 观测（spring.ai.advisor）

Advisor 执行时打点（含内层 Advisor 耗时）。

高基数：`spring.ai.advisor.name`、`spring.ai.advisor.order`——配合 ChatClient 的 advisors 列表，可以分析"哪个 Advisor 吃掉了延迟"。

## 4. ChatModel 观测（gen_ai.client.*）

`call`/`stream` 打点 + `gen_ai.client.token.usage` token 计量。

- 低基数：`gen_ai.operation.name`、`gen_ai.system`（提供商）、`gen_ai.request.model`、`gen_ai.response.model`
- 高基数：请求参数（temperature、top_k/p、max_tokens、stop_sequences、frequency/presence_penalty）、`gen_ai.response.finish_reasons`、`gen_ai.response.id`、token 用量（input/output/total）、`gen_ai.prompt`/`gen_ai.completion`（可选）、`spring.ai.model.request.tool.names`

⚠️ **支持范围**（当前）：Anthropic、Azure OpenAI、Mistral、Ollama、OpenAI、Vertex AI、MiniMax、Moonshot、QianFan、Zhipu——别家模型暂无观测。

**内容记录开关**：

```yaml
spring:
  ai:
    chat:
      observations:
        log-prompt: false
        log-completion: false
        include-error-logging: false   # 错误日志进观测
```

## 5. Tool Calling 观测（spring.ai.tool）

工具调用打点：`spring.ai.kind=tool_call`、`spring.ai.tool.definition.name`（低基数）；工具描述、参数 Schema、`spring.ai.tool.call.arguments`、`spring.ai.tool.call.result`（高基数，后两个要开关）。

```yaml
spring:
  ai:
    tools:
      observations:
        include-content: false   # 工具入参/结果进 span 属性（默认关）
```

## 6. EmbeddingModel / ImageModel 观测

- Embedding：`gen_ai.request.embedding.dimensions`、token 用量；支持 Azure OpenAI/Mistral/Ollama/OpenAI
- Image：`gen_ai.request.image.size/style/response_format`、token 用量；仅 OpenAI
- 图片 prompt 记录：`spring.ai.image.observations.log-prompt=false`

## 7. VectorStore 观测（db.vector.client.*）

**所有**向量库实现都有埋点：add/delete/query 打点。

- 低基数：`db.operation.name`（add/delete/query）、`db.system`（pg_vector、redis、milvus…）、`spring.ai.kind=vector_store`
- 高基数：`db.collection.name`、`db.vector.query.content/filter/top_k/similarity_threshold`、`db.vector.dimension_count`、`db.vector.query.response.documents`（可选）

```yaml
spring:
  ai:
    vectorstore:
      observations:
        log-query-response: false   # 检索结果内容进日志（默认关）
```

## 8. Prometheus 指标命名

Micrometer 点号命名，Prometheus 导出换下划线 + 后缀：

| 基名 | 导出序列 |
|------|---------|
| gen_ai.client.operation | `gen_ai_client_operation_seconds_{count,sum,max}` + `_active_count` |
| db.vector.client.operation | `db_vector_client_operation_seconds_{count,sum,max}` + `_active_count` |

| 指标 | 类型 | 说明 |
|------|------|------|
| `gen_ai_client_token_usage_total` | Counter | token 消耗，标签 `gen_ai_token_type=input/output/total` |
| `*_seconds_sum / *_seconds_count` | Timer | 平均延迟 = sum/count |
| `*_seconds_max` | Gauge | 高水位 |
| `*_active_count` | Gauge | **进行中**的调用（并发/负载） |

**Active vs Completed**：`active_count` 是瞬时在飞数；`_seconds_*` 只统计已完成——算平均延迟用 sum/count，排查卡顿看 active_count 和 max。

## 9. 配置属性改名（1.0.0-RC1）

```text
include-prompt → log-prompt（chat client / chat / image）
include-completion → log-completion
include-query-response → log-query-response（vectorstore）
include-input（chat client）→ 废弃，被 log-prompt 取代
```

## 10. 与前文串联

- ChatClient 的 `conversation.id` 标签 = 08 章的 `ChatMemory.CONVERSATION_ID`——按会话串 trace
- 工具观测 = 09 章"可观测性"小节的全貌（arguments/result 默认不导出）
- RAG 场景串起来：一次问答的 trace 里有 chat_client → advisor（检索增强）→ vector_store query → chat_model，全链路可追
- Advisor 的 name/order 标签呼应 02 章的执行顺序

## 11. 生产边界

- log-prompt / log-completion / tools include-content **默认全关是对的**——开了等于把用户数据写进 trace，先想脱敏和合规
- 高基数 key 只进 trace 不进 metrics 是防 Prometheus 基数爆炸，别乱往 metrics 塞 conversation id
- 用平均延迟（sum/count）+ active_count + max 三个一起看，单看一个会被骗
- 模型提供商不在支持列表里就没有 ChatModel 级观测，只能靠 ChatClient 层
- 接 Prometheus + Grafana +（可选）Zipkin/Tempo 是标准 Spring Boot 组合
