# 02 模型的创建与调用

> 来源：`尚硅谷-02-模型的创建与调用.pdf`。示例按当前项目的 LangChain 版本整理，平台地址、模型名称和默认参数应以实际提供商文档为准。

## 学习目标

- 理解 LangChain 在模型调用中的位置
- 掌握专用模型类、OpenAI 兼容接口和 `init_chat_model()`
- 使用环境变量管理 API Key 和 Base URL
- 掌握 `invoke`、`stream`、`batch` 和异步调用
- 看懂 `AIMessage`、Token 用量和响应元数据
- 区分普通参数、`model_kwargs`、`extra_body` 和运行配置

## 1. LangChain 如何封装模型调用

早期的 Model I/O 可以拆成：

```text
Prompt Template -> Model -> Output Parser
```

现在对话模型已经成为主流，输入和输出通常都是消息：

```text
SystemMessage / HumanMessage
        -> ChatModel
        -> AIMessage
```

LangChain 不提供大模型本身，它统一封装第三方模型服务，让上层的 Prompt、Tool、Agent 和 Runnable 可以使用一致接口。

## 2. 模型部署位置

### 2.1 在线模型

调用在线服务通常需要三个要素：

```text
model    模型名称
api_key  身份凭证
base_url API 地址
```

提供商可能提供：

- 专用 SDK 和专用 LangChain 集成
- OpenAI Compatible 兼容接口
- 两种方式同时提供

### 2.2 本地模型

Ollama 可以在本地下载并运行模型：

```text
安装 Ollama
-> 下载模型
-> 启动本地服务
-> 使用 ChatOllama 调用
```

```python
from langchain_ollama import ChatOllama

model = ChatOllama(model="qwen3:8b")
response = model.invoke("用一句话介绍你自己")
print(response.content)
```

本地模型不等于零成本，还要考虑显存、内存、推理速度、模型许可和运维成本。

## 3. 配置管理

本地开发可以把配置放在 `.env`：

```dotenv
MODEL_API_KEY=<your-api-key>
MODEL_BASE_URL=https://example.com/v1
MODEL_NAME=example-model
```

读取配置：

```python
import os

from dotenv import load_dotenv

load_dotenv(override=True)

api_key = os.getenv("MODEL_API_KEY")
base_url = os.getenv("MODEL_BASE_URL")
model_name = os.getenv("MODEL_NAME")
```

注意：

- `.env` 必须加入 `.gitignore`
- 不要在代码、日志和异常中输出完整 API Key
- 生产环境优先使用部署平台或密钥管理服务注入配置
- 服务启动时应检查必要变量是否存在

## 4. 创建模型的三种方式

### 4.1 使用提供商专用类

不同提供商通常有独立集成类，例如：

```python
from langchain_deepseek import ChatDeepSeek

model = ChatDeepSeek(
    model="deepseek-chat",
)
```

优点：

- 能直接使用提供商特有能力
- 参数名称和返回结构更贴近官方 SDK

缺点：切换提供商时需要修改类和部分参数。

### 4.2 使用 OpenAI 兼容接口

大量平台支持 OpenAI Compatible 协议，可以通过 `ChatOpenAI` 调用：

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model=model_name,
    api_key=api_key,
    base_url=base_url,
    temperature=0.2,
)
```

兼容接口只表示请求协议相似，不保证所有字段、工具调用、结构化输出和流式行为完全一致。

### 4.3 使用统一的 `init_chat_model()`

```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    model=model_name,
    model_provider="openai",
    api_key=api_key,
    base_url=base_url,
    temperature=0.2,
)
```

也可以把提供商写在模型字符串中：

```python
model = init_chat_model("openai:gpt-4.1-mini")
```

`init_chat_model()` 的价值是统一初始化入口。它会根据 `model_provider` 选择底层模型类，但不会抹平所有提供商能力差异。

### 4.4 如何选择

```text
需要提供商特有能力
-> 专用模型类

平台只提供 OpenAI 兼容接口
-> ChatOpenAI

需要统一配置和动态切换
-> init_chat_model
```

## 5. 常用初始化参数

| 参数 | 含义 |
|---|---|
| `model` | 模型名称 |
| `model_provider` | 模型提供商，仅统一初始化入口需要 |
| `api_key` | API 凭证 |
| `base_url` | 请求地址 |
| `temperature` | 输出随机性 |
| `max_tokens` / `max_completion_tokens` | 最大输出 Token，名称取决于模型类 |
| `timeout` | 请求超时 |
| `max_retries` | 客户端重试次数 |
| `top_p` | 核采样参数 |
| `seed` | 支持时用于提高可复现性 |

`temperature` 越低通常越稳定，越高通常越发散，但 `temperature=0` 也不保证绝对确定。分类、抽取和结构化输出通常使用较低随机性；创意写作可以适当提高。

不要假设课件或某个类展示的默认值适用于所有提供商。可以查看当前类的字段：

```python
print(type(model).model_fields)
```

## 6. `invoke()` 单次调用

### 6.1 字符串输入

```python
response = model.invoke("什么是 LangChain？")
print(response.content)
```

字符串通常会被转换为一条用户消息。

### 6.2 消息字典

```python
messages = [
    {"role": "system", "content": "你是 Python 教师"},
    {"role": "user", "content": "什么是装饰器？"},
]

response = model.invoke(messages)
```

### 6.3 消息对象

```python
from langchain_core.messages import HumanMessage, SystemMessage

messages = [
    SystemMessage(content="你是 Python 教师"),
    HumanMessage(content="什么是装饰器？"),
]

response = model.invoke(messages)
```

要实现多轮对话，必须把之前的用户消息和 AI 回复一起传入，或者使用 Agent Checkpointer 管理状态。模型 API 本身不会自动记住上一轮请求。

## 7. `AIMessage` 返回值

`invoke()` 通常返回 `AIMessage`：

```python
response = model.invoke("1 + 2 等于多少？")

print(response.content)
print(response.id)
print(response.response_metadata)
print(response.usage_metadata)
print(response.tool_calls)
print(response.invalid_tool_calls)
```

常见字段：

| 字段 | 含义 |
|---|---|
| `content` | 模型生成内容 |
| `id` | 本次消息或运行标识 |
| `response_metadata` | 提供商返回的模型、结束原因、延迟等信息 |
| `usage_metadata` | 输入、输出和总 Token |
| `tool_calls` | 合法工具调用 |
| `invalid_tool_calls` | 解析失败的工具调用 |

提供商返回的 Metadata 不完全统一，读取时应使用 `.get()`，不要假定所有字段都存在。

## 8. 流式调用

```python
for chunk in model.stream("解释一下 Transformer"):
    print(chunk.content, end="", flush=True)
```

`stream()` 返回迭代器，逐步产生 `AIMessageChunk`：

```text
invoke：等待完整响应后一次返回
stream：生成一个 Chunk 就返回一个 Chunk
```

流式输出改善首字等待体验，但还要处理：

- 客户端断开
- 中途异常
- Chunk 合并
- Tool Call 参数分片
- 最终 Token 用量

## 9. 批量调用

### 9.1 `batch()`

```python
inputs = [
    "北京是哪个国家的首都？",
    "1 + 2 等于多少？",
    "用一句话解释 RAG",
]

responses = model.batch(inputs)
```

结果顺序和输入顺序一致。批量不一定代表提供商提供了真正的批处理 API，LangChain 可能通过并发完成。

### 9.2 `batch_as_completed()`

```python
for index, response in model.batch_as_completed(inputs):
    print(index, response.content)
```

哪个请求先完成就先返回，因此顺序可能不同，`index` 用于关联原始输入。

## 10. 异步调用

常用异步方法：

```text
ainvoke()
astream()
abatch()
abatch_as_completed()
```

```python
import asyncio


async def main() -> None:
    response = await model.ainvoke("什么是异步调用？")
    print(response.content)


asyncio.run(main())
```

异步适合 I/O 密集型并发，不会让单次模型推理本身变快。必须设置并发上限、超时和速率限制。

## 11. 调用失败与重试

常见失败：

- API Key 或 Base URL 错误
- 模型名称不存在
- 网络超时
- 限流
- 余额不足
- 请求字段不兼容
- 上下文超过限制

```python
try:
    response = model.invoke("Hello")
except TimeoutError as exc:
    # 记录脱敏后的上下文并执行受控重试或降级
    raise RuntimeError("模型请求超时") from exc
```

只对临时错误重试，使用指数退避和最大次数；鉴权、参数和权限错误不应盲目重试。

## 12. `profile` 模型能力画像

部分模型集成提供 `profile`：

```python
print(model.profile)
```

它可能描述工具调用、结构化输出、上下文窗口等能力。`profile` 是否存在取决于 LangChain 集成声明，值为空不代表模型一定没有该能力。

## 13. `model_kwargs` 与 `extra_body`

### 13.1 `model_kwargs`

用于传递模型 API 的标准参数，但这些参数没有被当前模型类暴露为独立初始化字段：

```python
model = ChatOpenAI(
    model=model_name,
    model_kwargs={"some_standard_parameter": True},
)
```

已经有明确参数的位置应直接传递，不要在 `model_kwargs` 重复声明。

### 13.2 `extra_body`

用于 OpenAI 兼容厂商自己扩展的请求字段：

```python
model = ChatOpenAI(
    model=model_name,
    base_url=base_url,
    extra_body={
        "thinking": {"type": "enabled"},
    },
)
```

是否支持 `thinking` 等字段由实际服务商决定。

```text
LangChain 明确参数 -> 直接传
标准 API 的额外参数 -> model_kwargs
兼容厂商私有字段 -> extra_body
```

工具绑定优先使用 `bind_tools()`，不要把手写的 `tools` Payload 当作日常首选。

## 14. Runnable `config`

模型也是 Runnable，调用时可以传递配置：

```python
config = {
    "run_name": "answer_question",
    "tags": ["learning"],
    "metadata": {"scenario": "model-basics"},
    "configurable": {
        "temperature": 0.1,
    },
}

response = model.invoke("1 + 2 = ?", config=config)
```

常见配置：

| 配置 | 用途 |
|---|---|
| `run_name` | Trace 中的运行名称 |
| `tags` | 分类和过滤 |
| `metadata` | 记录非敏感业务元数据 |
| `callbacks` | 回调处理 |
| `max_concurrency` | 批量并发上限 |
| `configurable` | 运行时可替换字段 |

使用 `configurable` 覆盖模型参数时，需要在初始化时声明允许动态调整的字段：

```python
model = init_chat_model(
    model=model_name,
    model_provider="openai",
    configurable_fields=("model", "temperature"),
)
```

不要允许不可信用户任意覆盖模型、Base URL 或高成本参数。

## 总结

```text
创建模型：专用类 / ChatOpenAI / init_chat_model
管理密钥：环境变量或密钥服务
单次调用：invoke / ainvoke
流式调用：stream / astream
批量调用：batch / batch_as_completed
响应对象：AIMessage
扩展参数：model_kwargs / extra_body
运行追踪：Runnable config
```

模型初始化只是入口。后续 Message、Prompt、Structured Output、Tool 和 Agent 都建立在统一 ChatModel 接口之上。
