# 10. 工具调用节点

模型不会直接执行工具。它只在 `AIMessage.tool_calls` 中提出调用请求；应用读取请求、执行真实函数，再把 `ToolMessage` 交回模型。

## 10.1 手动工具循环

手动实现有助于理解完整协议：

```python
from langchain.messages import ToolMessage


def execute_tools(state: MessagesState) -> dict:
    ai_message = state["messages"][-1]
    tool_messages = []

    for call in ai_message.tool_calls:
        tool = tools_by_name[call["name"]]
        result = tool.invoke(call["args"])
        tool_messages.append(
            ToolMessage(
                content=str(result),
                tool_call_id=call["id"],
                name=call["name"],
            )
        )

    return {"messages": tool_messages}
```

关键约束：

- 只允许调用服务端注册的 Tool Allowlist。
- 参数必须经过 Schema、权限和业务三层校验。
- `ToolMessage.tool_call_id` 必须匹配模型请求中的 ID。
- 工具结果进入模型前要限制长度并处理敏感信息。

## 10.2 ToolNode

`ToolNode` 封装了 Tool Call 解析、工具匹配、执行和 ToolMessage 构造：

```python
from langchain.tools import tool
from langgraph.graph import END, START, MessagesState, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition


@tool
def get_weather(city: str) -> str:
    """查询指定城市的天气。"""
    return f"{city}：晴，25℃"


tools = [get_weather]
model_with_tools = model.bind_tools(tools)


def call_model(state: MessagesState):
    response = model_with_tools.invoke(state["messages"])
    return {"messages": [response]}


builder = StateGraph(MessagesState)
builder.add_node("agent", call_model)
builder.add_node("tools", ToolNode(tools))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", tools_condition)
builder.add_edge("tools", "agent")
graph = builder.compile()
```

`tools_condition` 检查最后一条 AIMessage：

- 存在 `tool_calls`：路由到默认名称为 `tools` 的 ToolNode。
- 不存在：路由到 `END`。

这样形成 `model -> tools -> model` 循环，直到模型返回普通答案。

## 10.3 ToolRuntime

Tool 参数分为两类：

- 模型可见参数：由 Tool Schema 暴露，例如 `city`、`order_id`。
- 可信运行参数：由框架注入，例如 State、Context、Config、Store 和 Tool Call ID。

```python
from dataclasses import dataclass
from langchain.tools import tool
from langgraph.prebuilt import ToolRuntime


@dataclass
class Context:
    user_id: str
    tenant_id: str


@tool
def get_order(order_id: str, runtime: ToolRuntime[Context, MessagesState]) -> dict:
    """查询当前用户的一笔订单。"""
    user_id = runtime.context.user_id
    tenant_id = runtime.context.tenant_id
    return order_service.get_owned_order(
        tenant_id=tenant_id,
        user_id=user_id,
        order_id=order_id,
    )
```

`runtime` 不会作为 Tool Schema 暴露给模型，因此模型无法伪造 `user_id` 来越权。

`ToolRuntime` 常用属性：

| 属性 | 含义 |
| --- | --- |
| `state` | 当前图 State |
| `context` | 应用传入的可信上下文 |
| `config` | Runnable 配置 |
| `store` | 长期记忆 Store |
| `tool_call_id` | 当前 Tool Call ID |
| `stream_writer` | 自定义流式事件写入器 |

## 10.4 工具更新 State

Tool 可以返回 `Command(update=...)`，同时写入业务字段和匹配的 ToolMessage：

```python
from langchain.messages import ToolMessage
from langchain.tools import tool
from langgraph.types import Command


@tool
def select_customer(
    customer_id: str,
    runtime: ToolRuntime[Context, State],
) -> Command:
    """选择当前会话正在处理的客户。"""
    customer = customer_service.get_owned_customer(
        user_id=runtime.context.user_id,
        customer_id=customer_id,
    )
    return Command(
        update={
            "selected_customer": customer,
            "messages": [
                ToolMessage(
                    content="客户已选择",
                    tool_call_id=runtime.tool_call_id,
                )
            ],
        }
    )
```

返回 `Command` 时仍要提供对应 ToolMessage，否则模型的 Tool Call 对话协议可能不完整。

## 10.5 错误处理

`ToolNode` 的 `handle_tool_errors` 支持多种策略：

```python
ToolNode(tools, handle_tool_errors=True)
ToolNode(tools, handle_tool_errors="工具执行失败，请检查参数")
ToolNode(tools, handle_tool_errors=(TimeoutError, ConnectionError))
ToolNode(tools, handle_tool_errors=format_tool_error)
```

建议区分：

- 参数错误：返回可修正的明确错误，让模型重新组织参数。
- 权限/业务拒绝：返回稳定状态，不允许模型通过重试绕过。
- 临时技术错误：由业务代码有限重试，再返回最终失败或未知状态。
- 编程错误：不要吞掉，记录并告警。

## 10.6 生产 Tool 设计

1. Tool 名称和描述明确，参数 Schema 尽量小。
2. 查询与写操作分开，危险写操作增加人工审批。
3. 用户、租户、权限来自 Runtime Context，不来自模型参数。
4. 业务幂等键由应用或业务服务维护。
5. Tool 返回短小、结构稳定，并明确 `SUCCESS`、`FAILED`、`UNKNOWN`。
6. 模型输出不是可信指令，Tool 内部必须重新校验。
7. 限制单轮 Tool 调用次数、总耗时和结果大小。
8. 日志记录 Tool Call ID、业务操作 ID、用户、参数摘要和结果状态。

ToolNode 只是执行适配器，不负责替代业务服务的权限、事务和幂等控制。
