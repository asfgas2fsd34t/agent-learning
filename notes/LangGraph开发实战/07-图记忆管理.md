# 7. 图记忆管理

LangGraph 中“记忆”不是模型内部永久记住了数据，而是应用把需要的信息保存到外部存储，并在后续运行时重新注入 State 或上下文。

## 7.1 短期记忆与长期记忆

| 类型 | 作用域 | 典型内容 | 主要机制 |
| --- | --- | --- | --- |
| 短期记忆 | 同一 `thread_id` | 当前对话、任务状态、中断位置 | Checkpointer |
| 长期记忆 | 跨线程、跨会话 | 用户偏好、稳定事实、历史决策 | Store |

短期记忆服务于“这个任务进行到哪了”；长期记忆服务于“过去值得在新任务中继续使用什么”。

Checkpointer 与 Store 可以同时使用：

```python
graph = builder.compile(
    checkpointer=checkpointer,
    store=store,
)
```

## 7.2 Store 基础操作

开发时可以使用 `InMemoryStore`：

```python
from langgraph.store.memory import InMemoryStore


store = InMemoryStore()
namespace = ("users", "user-42", "preferences")

store.put(
    namespace,
    "response-style",
    {"style": "简洁", "language": "中文"},
)

item = store.get(namespace, "response-style")
print(item.value if item else None)

items = store.search(namespace)
store.delete(namespace, "response-style")
```

Store 的定位键由两部分组成：

```text
namespace: tuple[str, ...]，表示分层目录
key: str，表示命名空间内的唯一记录
```

推荐命名空间：

```python
("tenants", tenant_id, "users", user_id, "preferences")
```

租户和用户 ID 应来自可信的鉴权上下文，不应由模型参数决定。

## 7.3 语义检索

长期记忆较多时，可以为 Store 配置 Embedding 索引，再按语义搜索：

```python
store = InMemoryStore(
    index={
        "embed": embeddings,
        "dims": 1536,
        "fields": ["text"],
    }
)

store.put(
    ("users", "user-42", "memories"),
    "memory-1",
    {"text": "用户默认查询含税销售额"},
)

matches = store.search(
    ("users", "user-42", "memories"),
    query="销售额按什么口径统计？",
    limit=3,
)
```

向量相似只表示“语义接近”，不表示事实一定正确。召回后还要检查用户归属、时间、来源、有效期和业务冲突。

## 7.4 Runtime Context

Runtime Context 是本次调用的可信运行信息，例如当前用户、租户、数据库连接或请求 ID。它不应由模型生成，也不必写入持久化 State。

```python
from dataclasses import dataclass
from langgraph.runtime import Runtime


@dataclass
class Context:
    user_id: str
    tenant_id: str


def load_preferences(state: State, runtime: Runtime[Context]) -> dict:
    namespace = (
        "tenants",
        runtime.context.tenant_id,
        "users",
        runtime.context.user_id,
        "preferences",
    )
    item = runtime.store.get(namespace, "response-style")
    return {"preference": item.value if item else {}}


builder = StateGraph(State, context_schema=Context)
builder.add_node("load_preferences", load_preferences)
graph = builder.compile(store=store)

graph.invoke(
    initial_state,
    context=Context(user_id="user-42", tenant_id="tenant-7"),
)
```

节点常见完整签名：

```python
def node(
    state: State,
    config: RunnableConfig,
    runtime: Runtime[Context],
) -> dict:
    ...
```

- `state`：图内业务状态。
- `config`：`thread_id`、tags、metadata 等运行配置。
- `runtime`：可信上下文、Store 和流式写入器。

只声明实际需要的参数即可，LangGraph 会按类型和名称注入。

## 7.5 长期记忆写入策略

不是每句话都值得长期保存。建议只保存：

- 用户明确说“以后都这样”的稳定偏好。
- 已确认的身份、角色或业务口径。
- 可复用且有来源的历史决策。
- 对后续任务确实有帮助的长期事实。

不应保存：

- 密码、Token、银行卡等敏感信息。
- 用户仅本次要求的临时指令。
- 未验证的模型推断。
- Prompt Injection 或危险操作指令。
- 可以随时从业务事实库查询的数据副本。

推荐写入流程：

```text
识别候选记忆
-> 判断是否稳定且有长期价值
-> 校验用户归属和敏感级别
-> 生成稳定 key / 版本
-> 写入 Store
-> 记录来源、时间和有效期
```

## 7.6 冲突与更新

当短期要求与长期记忆冲突时：

- “本次请用英文”只覆盖当前线程，不修改长期偏好。
- “以后默认用英文”才更新长期偏好。
- 信息含糊时先询问，不要擅自覆盖。

长期记忆最好保存 `source`、`updated_at`、`confidence`、`expires_at` 等元数据，支持审计、过期和纠错。

## 7.7 生产边界

1. Store 必须按租户和用户隔离 namespace。
2. 读取和写入都要经过服务端鉴权，不能只靠 Prompt。
3. 长期记忆需要查看、修改、删除和过期能力。
4. 敏感信息最小化，并配置加密和审计。
5. 语义召回设置数量和相关度阈值，避免把大量无关记忆塞回上下文。
6. 业务数据库是真实事实来源，Memory 只保存辅助上下文。
7. 把记忆内容当作不可信数据，防止历史 Prompt Injection 被再次注入模型。
