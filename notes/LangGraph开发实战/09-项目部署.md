# 9. 项目部署

LangGraph 本地服务化的核心是：把编译图暴露为可识别入口，通过 LangGraph CLI 启动 API，再使用 Studio、SDK 或聊天 UI 调试。

## 9.1 最小项目结构

```text
my-agent/
├── src/
│   └── agent.py
├── .env
├── langgraph.json
└── pyproject.toml
```

`src/agent.py` 必须导出编译后的图对象：

```python
from langgraph.graph import END, START, MessagesState, StateGraph


def answer(state: MessagesState):
    return {"messages": [model.invoke(state["messages"])]}


builder = StateGraph(MessagesState)
builder.add_node("answer", answer)
builder.add_edge(START, "answer")
builder.add_edge("answer", END)
graph = builder.compile()
```

## 9.2 langgraph.json

```json
{
  "dependencies": ["."],
  "graphs": {
    "assistant": "./src/agent.py:graph"
  },
  "env": ".env"
}
```

字段含义：

| 字段 | 作用 |
| --- | --- |
| `dependencies` | 服务启动时安装的本地或远程依赖 |
| `graphs` | 图名称到 Python 导出对象的映射 |
| `env` | 环境变量文件路径 |

图入口格式是 `文件路径:变量名`，变量必须是编译图，而不是 `StateGraph` builder。

## 9.3 本地启动

安装 CLI 对应依赖后，在项目目录运行：

```bash
langgraph dev
```

它会启动本地 API，并提供 Studio 调试入口。开发模式适合热更新和单机调试，不等于生产部署方案。

调试时重点观察：

- 每次 Run 的输入和最终输出。
- State 在节点间的变化。
- Tool Call 与 ToolMessage。
- 中断、错误和重试。
- Thread 与 Checkpoint 历史。
- 流式事件和耗时。

## 9.4 对接 LangSmith Studio

Studio 用于可视化图结构、创建 Thread、执行 Run、查看状态和恢复中断。配置 LangSmith 相关环境变量后，从 CLI 输出的 Studio 地址进入即可。

不要把 Trace 当成唯一业务日志。生产系统仍应保存业务操作 ID、用户、租户、权限结果和外部服务状态。

## 9.5 对接聊天 UI

Agent Chat UI 或自定义前端通常需要配置：

- LangGraph API 地址。
- Graph/Assistant ID。
- Thread ID。
- 可选的认证信息和用户上下文。

前端只负责发送消息和展示流式结果。用户身份、`thread_id` 归属、Tool 权限和敏感操作审批必须由后端校验。

## 9.6 生产部署边界

本地 `langgraph dev` 解决的是开发调试；生产还需要：

1. 可靠的 Checkpointer 和 Store，不使用进程内存保存关键状态。
2. 密钥管理，不提交 `.env` 和真实 API Key。
3. 身份认证、租户隔离和接口限流。
4. 数据库连接池、迁移、备份和容量规划。
5. 节点超时、重试、幂等和未知状态处理。
6. 日志、Metrics、Trace 和告警。
7. 图版本与 State Schema 的向后兼容。
8. 部署期间对运行中 Thread 和 Interrupt 的恢复策略。

## 9.7 常见问题

- **入口加载失败**：检查 `langgraph.json` 路径、变量名和依赖。
- **环境变量没有生效**：检查 `env` 路径和启动目录。
- **Studio 找不到图**：确认 `graphs` 映射和图已成功编译。
- **重启后历史消失**：仍在使用 InMemory Checkpointer。
- **前端能访问别人的线程**：后端没有校验 Thread 所属用户。
- **本地能运行，服务启动失败**：代码依赖了工作目录、未声明依赖或在模块导入阶段执行了副作用。
