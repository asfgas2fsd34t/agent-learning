# 12. 子图

子图是编译后的 LangGraph，被父图当作一个可复用执行单元。它适合隔离复杂流程、复用能力和控制状态边界。

## 12.1 两种嵌入方式

### 方式一：在父节点中调用子图

父子 State 不同，需要显式映射输入和输出：

```python
class ParentState(TypedDict):
    input_text: str
    final_text: str


class SubgraphState(TypedDict):
    raw_text: str
    cleaned_text: str


subgraph = sub_builder.compile()


def call_subgraph(state: ParentState) -> dict:
    result = subgraph.invoke({"raw_text": state["input_text"]})
    return {"final_text": result["cleaned_text"]}


parent_builder.add_node("clean_text", call_subgraph)
```

优点：状态边界清晰，可以在适配层转换字段。缺点：需要手工处理输入输出、配置和流式事件。

### 方式二：编译子图直接作为节点

父子图共享至少一部分 State 字段时，可以直接嵌入：

```python
subgraph = sub_builder.compile()

parent_builder.add_node("research", subgraph)
parent_builder.add_edge(START, "research")
```

共享字段通过 State 通道自动通信。子图私有字段不会自动成为父图公开输出，但字段名和 Reducer 仍要避免意外冲突。

| 需求 | 推荐方式 |
| --- | --- |
| 父子 State 完全不同 | 父节点中调用并映射 |
| 父子图共享业务 State | 子图直接作为节点 |
| 需要严格适配和权限过滤 | 包装节点 |
| 希望父图可视化子图结构 | 直接嵌入 |

## 12.2 子图持久化策略

父图配置 Checkpointer 后，嵌入子图可以参与同一持久化体系。子图编译策略决定子图状态的生命周期：

| 子图编译方式 | 语义 |
| --- | --- |
| `sub_builder.compile()` | 每次调用隔离，同时可借用父图 Checkpointer 支持中断恢复 |
| `sub_builder.compile(checkpointer=True)` | 子图按线程保留自己的跨调用历史 |
| `sub_builder.compile(checkpointer=False)` | 子图无检查点，不支持内部中断恢复 |

大多数子流程使用默认方式。只有子图本身确实需要跨调用记忆时才使用 `checkpointer=True`，否则多次调用同一子图时容易出现历史串扰。

子图的检查点使用独立 `checkpoint_ns`，与父图和其他子图隔离。

## 12.3 查看子图状态

```python
snapshot = parent_graph.get_state(config, subgraphs=True)
```

`subgraphs=True` 会展开子图任务中的状态快照。子图正在运行且未暂停时，内部状态未必可从外部稳定读取；这个能力主要用于中断和调试。

读取时关注：

- 父图 `values` 和 `next`。
- `tasks` 中对应子图任务。
- 子图自己的 `values`、`next` 和 `interrupts`。
- `checkpoint_ns`，它标识具体子图实例。

## 12.4 子图流式输出

```python
for namespace, chunk in parent_graph.stream(
    initial_state,
    stream_mode="updates",
    subgraphs=True,
):
    print(namespace, chunk)
```

父图和子图可能存在同名节点，消费端应把 `namespace` 作为事件路径的一部分。

如果在普通父节点里手动 `subgraph.invoke()`，流式传播取决于调用方式和运行配置。需要完整事件时优先使用直接嵌入，或显式使用子图的 `stream/astream` 转发事件。

## 12.5 子图动态路由

子图与普通节点一样，可以作为条件边或 `Command` 的目标：

```python
parent_builder.add_node("billing_flow", billing_subgraph)
parent_builder.add_node("support_flow", support_subgraph)


def route(state: ParentState):
    return "billing_flow" if state["intent"] == "billing" else "support_flow"


parent_builder.add_conditional_edges("classify", route)
```

动态路由前先完成结构化意图识别和权限检查。不能仅凭模型的一段自然语言结果直接进入危险子流程。

## 12.6 子图设计原则

一个子图应该围绕完整能力拆分，例如“退款审批”“研究报告生成”“客户资料补全”，而不是机械地把每两个节点包装成一张子图。

好的子图接口包括：

- 小而稳定的输入 Schema。
- 明确的输出 Schema。
- 内部私有 State。
- 可识别的错误和中断协议。
- 独立测试和可视化。

## 12.7 易错点

1. 父子 State 同名字段语义不同，导致意外合并。
2. 子图并行更新共享字段，却没有 Reducer。
3. 所有子图都设置 `checkpointer=True`，产生不必要的历史耦合。
4. 父节点手动调用子图时遗漏 `config`、`context` 或流式事件。
5. 子图内部执行危险操作，却只在父图入口鉴权一次。
6. 升级子图节点名称或 State Schema 后，旧 Checkpoint 无法恢复。
7. 子图层级过深，Trace 和状态定位困难。

## 12.8 测试建议

- 单独测试子图输入到输出。
- 在父图中测试状态映射和 Reducer。
- 测试子图失败、中断和恢复。
- 使用相同 `thread_id` 重复调用，确认是否符合预期记忆策略。
- 开启 `subgraphs=True` 检查流式事件路径。
