# 5. 节点执行与容错机制

节点可能调用模型、HTTP、数据库和文件系统，因此必须区分临时失败、永久失败、超时和可缓存计算。LangGraph 提供节点级重试、超时、错误处理和缓存。

## 5.1 整体执行顺序

```text
执行节点
-> 成功：合并状态更新
-> 失败或超时：RetryPolicy 判断是否重试
-> 重试耗尽：进入 error_handler
-> handler 成功：写入兜底更新或改道
-> handler 也失败：图运行失败
```

重试和恢复会导致节点再次执行，因此有副作用的节点必须考虑幂等。

## 5.2 重试 RetryPolicy

```python
from langgraph.types import RetryPolicy


builder.add_node(
    "call_api",
    call_api,
    retry_policy=RetryPolicy(
        max_attempts=3,
        initial_interval=0.5,
        backoff_factor=2.0,
        max_interval=10,
        jitter=True,
        retry_on=(TimeoutError, ConnectionError),
    ),
)
```

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `max_attempts` | 3 | 包含首次调用在内的最大尝试次数 |
| `initial_interval` | 0.5 秒 | 第一次重试前等待时间 |
| `backoff_factor` | 2.0 | 每次等待时间的增长倍数 |
| `max_interval` | 128 秒 | 最大等待间隔 |
| `jitter` | `True` | 增加随机抖动，避免并发重试风暴 |
| `retry_on` | 默认判断函数 | 异常类型、异常类型元组或判断函数 |

只重试临时性错误：网络超时、限流、短暂不可用。不要重试参数错误、权限错误、余额不足或确定性的业务拒绝。

```python
def should_retry(exc: Exception) -> bool:
    return isinstance(exc, ConnectionError)


policy = RetryPolicy(max_attempts=3, retry_on=should_retry)
```

## 5.3 超时

节点可以直接设置秒数，也可以使用 `TimeoutPolicy`：

```python
from langgraph.types import TimeoutPolicy


builder.add_node(
    "call_model",
    call_model,
    timeout=TimeoutPolicy(run_timeout=60),
)
```

也可以写 `timeout=60`。超时限制单次节点尝试；是否重试仍由 `RetryPolicy` 决定。

超时不等于外部操作被取消成功。例如支付服务已经接收请求，但本地等待超时，真实结果可能是 `UNKNOWN`。此时应使用业务幂等键并查询最终状态，不能盲目重新发起一笔新操作。

## 5.4 错误处理 error_handler

错误处理器在节点最终失败后执行。处理器通过类型为 `NodeError` 的参数读取失败节点和原始异常：

```python
from langgraph.errors import NodeError
from langgraph.types import Command


def handle_api_error(state: State, error: NodeError) -> Command:
    return Command(
        update={
            "status": "degraded",
            "error": str(error.error),
        },
        goto="fallback",
    )


builder.add_node(
    "call_api",
    call_api,
    retry_policy=RetryPolicy(max_attempts=3),
    error_handler=handle_api_error,
)
```

适合返回降级结果、切换备用服务或进入补偿节点。不适合吞掉所有错误后假装成功；最终结果应能区分 `SUCCESS`、`FAILED`、`UNKNOWN`。

## 5.5 节点缓存

缓存用于相同输入下可复用的昂贵计算，与 Checkpointer 的用途不同：

- Cache：避免重复计算。
- Checkpointer：保存图状态和执行进度。

启用缓存需要同时配置节点策略和缓存后端：

```python
from langgraph.cache.memory import InMemoryCache
from langgraph.types import CachePolicy


builder.add_node(
    "embed_document",
    embed_document,
    cache_policy=CachePolicy(ttl=300),
)

graph = builder.compile(cache=InMemoryCache())
```

`CachePolicy` 主要参数：

| 参数 | 作用 |
| --- | --- |
| `ttl` | 缓存有效秒数；`None` 表示不按时间过期 |
| `key_func` | 根据节点输入生成缓存键 |

默认键基于可序列化输入生成。输入中包含时间戳、随机 ID 或不稳定对象时，缓存命中率会很低。

不要缓存依赖实时数据、权限上下文或有副作用的节点。多租户系统的自定义缓存键必须包含租户和权限边界，避免跨用户命中。

## 5.6 全图默认策略

多个节点使用相同策略时可以设置默认值，节点自己的配置优先：

```python
builder = StateGraph(State).set_node_defaults(
    retry_policy=RetryPolicy(max_attempts=3),
    timeout=30,
)

builder.add_node("a", node_a)
builder.add_node(
    "slow_node",
    slow_node,
    timeout=120,  # 覆盖默认值
)
```

默认策略不会自动传递给子图。`retry_policy` 和 `timeout` 也会应用到错误处理节点；缓存和错误处理默认值不会应用到错误处理节点本身。

## 5.7 生产设计原则

1. **先分类错误再重试**：永久错误快速失败。
2. **重试必须有限**：同时设置次数、超时和总任务截止时间。
3. **副作用必须幂等**：重试键由业务服务生成或维护，不由模型自由生成。
4. **未知状态单独处理**：超时后先查状态，不重复创建业务操作。
5. **缓存隔离权限**：缓存键包含租户、用户或权限版本。
6. **保留可观测信息**：记录节点、尝试次数、异常类型、耗时和最终状态。
7. **不要把所有异常都转成正常答案**：不可恢复错误应显式失败并告警。

## 5.8 机制选择

| 问题 | 机制 |
| --- | --- |
| 网络抖动、短暂限流 | RetryPolicy |
| 外部服务可能长时间不返回 | timeout |
| 重试后需要降级或补偿 | error_handler |
| 同输入的纯计算成本高 | CachePolicy |
| 多个节点策略相同 | set_node_defaults |
| 进程崩溃后恢复流程 | Checkpointer，见第 06 篇 |
